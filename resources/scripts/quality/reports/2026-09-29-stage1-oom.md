## Heap inventory

A read-only HPROF scan completed over the entire dump. Counts:
- 44,721,794 java.lang.Long objects.
- 34,976,416 OlafHit objects.
- 11,295,726 HashMap.TreeNode objects and 3,639,579 HashMap.Node objects.
- 2,391,747 OlafFingerprint objects.

Histogram and replay status saved under ../oom-replay/. Serialized field byte
counts and HPROF instance-size fields are NOT HotSpot retained/shallow heap
sizes; no dominator or per-window ownership analysis has been performed.

Code inspection: processQueryQueue builds expandedHashes, nearToOriginal and
hashList for the entire window before SQL batches, then retains all returned
OlafHit objects in matchAccumulator until all batches complete. Batch size 1000
bounds query size, not total memory. This agrees with the huge hit and boxed
hash/map inventory. Next fix should bound representation/processing memory
while preserving all recognition evidence, followed by this exact recording
and positive-match parity checks. Simply truncating hits would risk quality.
